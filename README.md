# Student Management REST API

A backend application built with **Java, Play Framework 3.0.12, and MySQL** to manage student records through RESTful APIs. The application supports CRUD operations (Create, Read, Update, and Delete) and uses a layered architecture to separate controllers, business logic, and database access.

## Features

- Create a student record
- Retrieve all students
- Retrieve a student by ID
- Update student details
- Delete a student record
- Validate incoming JSON data
- Return HTTP status codes for successful and unsuccessful requests
- Connect to MySQL using JDBC and prepared statements

## Tech Stack

- **Language:** Java
- **Framework:** Play Framework 3.0.12
- **Database:** MySQL
- **Database connectivity:** JDBC, MySQL Connector/J
- **Build tool:** sbt
- **API testing:** Postman
- **Data format:** JSON

## 2. Create the MySQL Database

Open MySQL Workbench or your MySQL command-line client and execute:

```sql
CREATE DATABASE student_db;

USE student_db;

CREATE TABLE students (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    age INT NOT NULL,
    course VARCHAR(100) NOT NULL
);
```

Optional: Insert a sample record to test the GET endpoints.

```sql
INSERT INTO students (name, age, course)
VALUES ('Ananya', 21, 'Java');

SELECT * FROM students;
```

## 3. Configure the Database Connection

Open:

```text
conf/application.conf
```

Configure the default database connection using your local MySQL details:

```hocon
db.default.driver = "com.mysql.cj.jdbc.Driver"
db.default.url = "jdbc:mysql://localhost:3306/student_db"
db.default.username = "root"
db.default.password = "YOUR_MYSQL_PASSWORD"
```

Replace `YOUR_MYSQL_PASSWORD` with your local MySQL password.

**Security:** Do not commit real database passwords, API keys, or other secrets to GitHub. For a public repository, use environment variables or another secure configuration method and keep private configuration out of version control.

## 4. Check Dependencies

The project should include the Play JDBC module and MySQL Connector/J in `build.sbt`. For example, the dependency list may contain:


Keep the other dependencies generated by your Play project. Do not replace your entire `build.sbt` with this snippet; add the required dependencies to the existing list and avoid duplicates.

### Troubleshooting

**Port 9000 is already in use**

In PowerShell, identify the process using the port:

```powershell
netstat -ano | findstr :9000
```

Check the process name using the PID shown at the end of the output:

```powershell
tasklist /FI "PID eq <PID>"
```

Stop it only if you have confirmed it is an old process that is safe to terminate. Alternatively, stop the existing Play server from its terminal.

**Database connection error**

- Confirm that MySQL Server is running.
- Verify the database name, username, password, and port.
- Confirm that the MySQL JDBC dependency is included in `build.sbt`.
- Check the startup logs for the underlying error.

**Compilation or routes error**

- Check Java syntax and package names.
- Confirm that controller method names match `conf/routes`.
- Remove unsupported settings from `build.sbt` if your installed Play version does not recognize them.
- Review the first meaningful error in the terminal output.

## API Endpoints

Base URL: `http://localhost:9000`

| Method | Endpoint | Description | Typical success status |
|---|---|---|---|
| GET | `/students` | Retrieve all students | `200 OK` |
| GET | `/students/:id` | Retrieve a student by ID | `200 OK` |
| POST | `/students` | Create a student | `201 Created` |
| PUT | `/students/:id` | Update a student | `200 OK` |
| DELETE | `/students/:id` | Delete a student | `204 No Content` |

For missing student IDs, the API is designed to return `404 Not Found`. Invalid request data is designed to return `400 Bad Request`.

## Test with Postman

### 1. Create a Student

- **Method:** `POST`
- **URL:** `http://localhost:9000/students`
- **Body:** Select **raw → JSON**

```json
{
  "name": "Ananya",
  "age": 21,
  "course": "Java"
}
```

Expected response: `201 Created`, with the newly created student details and generated ID.

### 2. Retrieve All Students

- **Method:** `GET`
- **URL:** `http://localhost:9000/students`

Expected response: `200 OK`, with a JSON array of student records.

### 3. Retrieve One Student

- **Method:** `GET`
- **URL:** `http://localhost:9000/students/1`

Replace `1` with an ID that exists in your database.

Expected response: `200 OK` if the student exists, or `404 Not Found` otherwise.

### 4. Update a Student

- **Method:** `PUT`
- **URL:** `http://localhost:9000/students/1`
- **Body:** Select **raw → JSON**

```json
{
  "name": "Ananya Sharma",
  "age": 22,
  "course": "Play Framework"
}
```

Replace `1` with the ID of the student you want to update.

Expected response: `200 OK` if the student exists.

### 5. Delete a Student

- **Method:** `DELETE`
- **URL:** `http://localhost:9000/students/1`

Replace `1` with the ID of the student you want to delete.

Expected response: `204 No Content` if the record was deleted successfully.

```sql
SELECT * FROM students;
```

Use this query after POST, PUT, and DELETE to confirm that the database records changed as expected.

## Architecture

The application separates responsibilities into layers:

- **Model:** Represents student data.
- **Controller:** Receives HTTP requests and returns responses.
- **Service:** Validates input and coordinates application logic.
- **Repository:** Executes SQL queries using JDBC.
- **MySQL:** Stores student records.

Typical request flow:

```text
Postman
   |
   v
Routes
   |
   v
StudentController
   |
   v
StudentService
   |
   v
StudentRepository
   |
   v
MySQL Database
```
